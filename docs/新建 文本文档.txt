你现在是一名资深 Minecraft Java Mod / AI Agent / Pathfinding 工程师。

你的任务是为当前项目 CRPI-FakePlayer 实现一套高质量、可扩展、适合 FakePlayer 的 Minecraft 寻路与移动系统。

==================================================
一、项目目标
==================================================

为 CRPI-FakePlayer 增加完整的 Navigation / Pathfinding 系统。

目标不是实现一个简单的 A*。

目标是实现一个类似 Baritone 的 Minecraft Agent Navigation Engine：

World
 ↓
Goal
 ↓
Path Planning
 ↓
Movement Calculation
 ↓
A*
 ↓
Path
 ↓
Path Executor
 ↓
FakePlayer Control
 ↓
Minecraft Physics
 ↓
实际移动

系统必须支持动态重规划、障碍检测、跳跃、下落、台阶、Parkour、卡死检测、路径失败恢复，以及未来扩展挖掘/放置/交互能力。

 ↓

 ↓

 ↓

 ↓

 ↓

 ↓

 ↓

 ↓

 ↓

作为唯一邻居。

邻居必须由 Movement 系统产生。

==================================================
十九、Lookahead Planning
==================================================

参考 Baritone。

不要：

Path 完全走完
 ↓
重新计算

而应该：

当前 Path 执行
 +
后台计算下一段 Path

例如：

Path A：

A → B → C → D

执行到：

B

后台开始：

D → E → F → G

然后：

SplicedPath：

A → B → C → D → E → F → G

这样实现长距离导航。

==================================================
二十七、Tick 模型
==================================================

Navigation 必须基于 Minecraft Tick。

每 tick：

1. 更新世界状态
2. 更新当前 Movement
3. 更新 FakePlayer 状态
4. 检查 Movement 完成
5. 检查 Stuck
6. 检查 Path 是否失效
7. 判断是否 Repath
8. 执行 Control

禁止使用大量独立线程直接修改 Minecraft Entity 状态。

Path Calculation 可以异步。

Minecraft World / Entity 的实际修改必须回到正确的 Minecraft Thread。
